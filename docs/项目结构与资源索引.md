
## 2. 多版本机制（Stonecutter）

- `settings.gradle`：stonecutter 0.9.8，`versions '1.20.1', '1.21.1'`，`vcsVersion = '1.21.1'`
- `stonecutter.gradle`：`stonecutter.active '1.21.1'`
- 共用源码在 `src/main`，版本差异用预处理注释：`//? if <1.20.2 { ... //?}`（Groovy DSL 开着 hard mode）
- 版本参数（依赖版本、parchment 映射）在各节点 `versions\<版本>\gradle.properties`：
  - 1.21.1：NeoForge 21.1.250、农夫乐事 1.21.1-1.3.4、Create 6.0.10+mc1.21.1、Jade 15.10.6、JEI 19.51.0.418、果园乐事 1.2.14（仅 dev 测试，不是前置）
  - 1.20.1：Forge 47.1.33（声明范围 `[47.1.0,48)`，玩家侧 47.4.26 兼容）、农夫乐事 1.20.1-1.3.4、Create mc1.20.1-6.0.8、Jade 11.13.3、JEI 15.20.0.106、MixinExtras 0.4.1
- 打包模板：NeoForge 在 `src/main/templates/META-INF/neoforge.mods.toml`，1.20.1 在 `src/main/templates-forge/META-INF/mods.toml`（外加 `pack.mcmeta`）

### 1.20.1 数据降级

`gradle/legacy-data-port.groovy` 在 1.20.1 节点构建时执行，做这些事：

- 目录/文件改名：`advancement`→`advancements`、`recipe`→`recipes`、`structure`→`structures`、`loot_table`→`loot_tables`
- 命名空间：`neoforge:` → `forge:`（biome_modifier、data_maps 等）
- JSON 键名：`id`→`item`（ingredient）等
- 细节以脚本头部注释为准

| `textures/block/`、`textures/item/` | 1883 | 全部贴图 |

贴图命名规律：

- 菜肴：`<dish>_dish.png`（盘装）/`_flat.png`（平铺）/`_p1~p3.png`（不同分量）；锅装 `<dish>_pot_stew.png`
- 串：`chili_skewer_top_stage1~4`、`corn_skewer_bottom_stage1~4` 一类；串的阶段 3（摘空）共用一张"线"贴图，带透明通道
- 大缸/缸坯：`vat_*` 系列

串类方块模型的 `render_type` 用 `minecraft:tripwire`（不是 `translucent`）：原版绊线层会丢弃全透明像素，交叉摆放时不会互相遮挡。改前用过 `translucent`，全透明像素仍写深度，会把交叉的另一面顶掉。

## 9. 已知坑（维护提示）

- 1.20.1 的 `neoforge:` 命名空间由 `gradle/legacy-data-port.groovy` 转成 `forge:`，资源按 1.21 写法写，别手写 `forge:`
- JEI 必须按 15.20.0.106 编译（新版 `addFluidStack` 描述符在 15.20 不存在，会 NoSuchMethodError），已在 `versions/1.20.1/gradle.properties` 里锁死
- Create 的 `FanProcessingType.getAt` 按 priority 降序取第一个 `isValidAt` 为真的类型。本模组"干燥"类型只在鼓风机正前方一格成立；早期无条件 return true 会让整合包里鼓风机全部失效（见 `compat/create/ModFanProcessingTypes.java` 注释）
- 起客户端要带 `GRADLE_OPTS` 里的 daemon registry 重定向，否则可能报 registry.bin 写入失败
